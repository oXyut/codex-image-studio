# Codex Image Studio

ChatGPTでログイン済みの公式Codex CLIを使って画像を生成する、個人向けのローカルWebアプリです。

日本語プロンプトと、要素別のテンプレートの保存・検索・組み合わせに対応します。過去の画像の拡大プレビューや参照、サイズ・スタイル・透過背景の指定に対応します。生成状況の確認、待機キュー、キャンセル、履歴検索、再試行、ダウンロードにも対応します。

## 起動

Node.js 22.12以上と、画像生成に対応したCodex CLIが必要です。フロントエンドはReact・TypeScript・shadcn/uiで構成しています。サーバー、共通処理、テスト、補助スクリプトもTypeScriptで記述しています。初回起動時や依存パッケージの変更後は、`npm ci`でパッケージをインストールしてください。

```sh
cd ~/work/codex-image-studio
npm ci
npm run doctor
npm run dev
```

ブラウザで <http://127.0.0.1:4317> を開いてください。停止するには`Ctrl+C`を押します。既に起動中の場合は、そのURLを開くだけで利用できます。

`npm run dev`と`npm start`は、起動前にTypeScriptのサーバーとViteのフロントエンドをビルドします。サーバーの実行ファイルは`dist/server.js`、画面の配信用ファイルは`public/build/`に出力します。起動後に画面だけを変更した場合は`npm run build:frontend`を実行し、ブラウザを再読み込みしてください。サーバーや共通処理を変更した場合は、サーバーを停止して`npm run dev`で起動し直してください。

ログインが必要な場合は`codex login`を実行してChatGPT認証を選びます。ログイン済みの認証ファイルはアプリから直接読みません。Codex CLIが認証を管理します。

## 画面の使い分け

ナビゲーションから「制作」「履歴」「系統図」「テンプレート」の独立した画面を切り替えます。広い画面では左のサイドバー、狭い画面では上部のナビゲーションを使います。画面を切り替えても制作中の下書きは保持します。

| 画面 | 使い方 |
| --- | --- |
| 制作 | プロンプト・テンプレート・参照画像を組み合わせ、生成設定と枚数を指定します。生成ボタンと枚数は入力パネルの下部に表示します。 |
| 履歴 | 生成画像を検索・絞り込みし、選んだ画像の入力や設定を確認します。参照への追加、元の入力の読み込み、再生成、ダウンロード、ゴミ箱への移動もここから行えます。 |
| 系統図 | 画像の参照関係や別案の枝をたどります。選択した画像の詳細から、続きを制作できます。 |
| テンプレート | 一覧と選択した要素の本文・履歴を確認します。新規作成・編集は独立したダイアログで行います。 |

画像カード、制作の生成結果・同時作成のサムネイル、画像詳細・拡大プレビュー、系統図の画像ノードを右クリックすると、その画像の操作メニューを開けます。拡大・参照追加・お気に入り・ダウンロード・系統図への移動・入力の編集・再生成・ゴミ箱への移動に対応し、生成中は停止も選べます。右クリックだけでは画像選択や生成を行わず、削除は対象確認画面を開きます。テンプレート一覧の行では、編集・制作での利用・履歴と差分・お気に入り・アーカイブと復元を選べます。通常の操作ボタンも引き続き使えます。対象にフォーカスして `Shift+F10` またはメニューキーでも開き、矢印キーで選び、`Escape` で閉じられます。

制作で要素を選ぶダイアログと、保存済みの要素を管理する画面を分けています。参照画像は生成済み画像とアップロード画像を一つのダイアログで選択し、画像ごとの役割を指定してから反映できます。

## テンプレートを組み合わせる

1. 制作画面の「テンプレート」で「追加」または「テンプレートを選ぶ」を開きます。
2. 名前・本文・タグで検索し、服装、顔立ち、表情、髪型、体型・ポーズ、背景、色味、撮影、光、画風、ネガティブプロンプト、その他で絞り込みます。お気に入りでも絞れます。
3. 必要な要素を追加します。制作画面で上下に並べ替えたり、外したりできます。選択ダイアログには、追加済みの要素の利用中の版を表示します。
4. プロンプトの確認を開くと、入力文と要素を組み合わせた本文が確認できます。

テンプレートの名前は80文字、本文は2,000文字までです。タグは12個までで、各40文字までです。1回に最大12要素を組み合わせ、合計12,000文字まで送れます。テンプレートだけでも生成でき、基本の入力文は4,000文字までです。初回起動時にサンプル7件を保存します。

新規保存・編集は「テンプレート」画面で行います。選択ダイアログの「テンプレートを管理」からも移動できます。「新しいテンプレート」や選択した要素の「編集」で入力ダイアログを開きます。制作画面から入力を保存する場合は、本文を引き継いで新規作成します。

名前は本文から80文字以内で自動入力し、改行や連続する空白は1つの空白にまとめます。短い本文なら名前にも同じ内容が入り、本文の変更に合わせて更新します。名前を手動で変えると、以後はその名前を保持します。名前を空にすると、次の本文入力で自動入力を再開します。制作画面から引き継いだ本文にも自動入力が適用され、既存のテンプレートは名前が本文から自動入力した内容と同じ場合に本文の変更に追従します。

アーカイブしたテンプレートは通常の一覧から外れ、「アーカイブ」タブから復元できます。データは`data/templates.json`に保存します。

生成履歴には、選んだ要素のその時点の内容を保存します。後でテンプレートを編集・アーカイブしても、過去の入力を再利用できます。下書きに追加済みの要素を新しい版に置き換える場合は、選択ダイアログの「更新」を押します。

## テンプレートのバージョンと差分

管理画面でテンプレートを選ぶと、現在の版と「本文」「履歴・差分」のタブを表示します。名前・本文・分類・タグ・お気に入り・アーカイブ状態の変更を保存し、任意の2つの版を比較できます。本文の追加・削除は行ごとに色付きで表示します。

「vN を制作に追加」で過去版を直接利用できます。「vN の内容を新しい版として復元」は、その内容を新しい版として保存し、途中の履歴も保持します。生成履歴には利用した版と本文を保存するため、後の編集・復元で生成時の入力は変わりません。別画面で先に更新された場合は保存を止め、編集中の入力を保持します。「最新を読み込む」を押したときに、入力を最新の内容へ置き換えます。

既存のテンプレートは現在の内容をv1として自動移行します。機能追加前に保存されていなかった編集内容は復元できません。履歴も`data/templates.json`に保存します。

## まとめて生成する・アスペクト比を指定する

「生成件数」で1〜10件を指定します。同じ文章・テンプレートの版・参照画像・設定で別案を並列に生成します。既定では最大5件を同時に実行し、枠が空くと待機中の画像の生成を開始します。`.env`の`GENERATION_CONCURRENCY`で同時実行数を1〜10件に変更できます。

まとめて生成した画像では、グループごとの進捗確認、履歴の絞り込み、個別の結果表示に対応します。待機中の残りと生成中の画像をまとめてキャンセルできます。待機キューに指定件数すべての空きがない場合は、生成前にエラーを表示します。

再生成では、現在の制作画面で指定した枚数を使います。文章・テンプレート・参照画像・サイズ・スタイル・透過設定は、元画像を生成したときのものを使用します。現在入力中の文章やアスペクト比は反映しません。操作メニューにも、元の設定と現在の枚数で生成することを表示します。複数の別案はそれぞれ独立した枝として同じ元画像につながり、別案同士を参照する関係は作りません。

サイズの「自動」では、寸法や固定比率を強制せず、説明と参照画像の構図に適した比率を画像ツールに選ばせます。新しい下書きの初期選択は自動ですが、保存済みの下書きや生成履歴のサイズは保持します。固定サイズには1:1・3:2・2:3・16:9（1600×900指定）・9:16（900×1600指定）があります。最終的な画像サイズはツールの出力によります。

## 生成画像をお気に入りにする

生成した完成画像は、履歴のカード、制作画面、画像の詳細・拡大プレビューにある星ボタンでお気に入りに追加・解除できます。履歴の「お気に入りのみ」は検索・状態・同時作成の絞り込みと併用できます。お気に入りは`data/jobs/<ID>/job.json`に保存し、再起動後やゴミ箱からの復元後にも保持します。再生成や派生で新しく作った画像には引き継ぎません。

## 過去の画像を参照にする

履歴・系統図の画像は、1回のクリックで拡大プレビューを開きます。初期表示では、画像の縦横比を保って画面内に大きく収め、プロンプト・参照元・タイトルとメモの詳細パネルも開きます。「詳細」でパネルを開閉でき、プレビューを閉じて再度開くと展開済みに戻ります。生成中や失敗した履歴には状態と操作を表示します。制作画面の拡大ボタンでも同じプレビューを開きます。

画像をクリックすると、その位置を中心に2倍へ拡大し、ドラッグで表示位置を動かせます。スクロール、倍率スライダー、＋・−で全体表示の100〜800%を指定し、「全体表示」で倍率と位置を戻せます。前後の完成画像は左右のボタンか矢印キーで切り替えます。拡大・移動中の画像にフォーカスしている間は矢印キーで位置を動かし、＋・−で倍率を調整、0キーで全体表示に戻します。Escapeで閉じます。

「参照に追加」を押すと制作画面にサムネイルを表示し、入力中の文章・テンプレート・設定は保持します。最大4枚まで選び、全体・人物・顔立ち・髪型・服装・ポーズ・背景・色味・構図・画風から、引き継ぐ要素を指定します。変更したい内容を文章に書き、生成してください。

参照元には、このアプリで完成した画像と、手元からアップロードしたPNG/JPEG/WebPを使用できます。サーバーで参照IDを検証し、ジョブの作業フォルダに画像をコピーして、CLIの`localImage`入力と画像ツールの`referenced_image_paths`に渡します。ブラウザから任意のファイルパスは受け付けません。

## 手元の画像を起点にする

制作画面の「参照画像」から選択ダイアログを開き、ファイルを選ぶかドロップしてアップロードします。「すべて」「生成画像」「アップロード」のタブと検索から保存済み画像も選べます。生成済み画像と合わせて最大4枚を選び、引き継ぐ要素を指定して「選択を反映」を押します。選択のキャンセルでは制作中の参照を変更しません。アップロード中は生成ボタンを無効にします。

対応する形式は静止画のPNG・JPEG・WebPで、1枚10MBまでです。各辺16,384px以内、4,000万画素以内に制限しています。形式と内容を検証し、破損した画像・アニメーション・SVG・HEICなどにはエラーを表示します。エラー時も入力済みの文章・テンプレート・参照を保持します。

アップロード画像の原本は加工せずに保存します。保存先は`data/uploads/<ID>/`で、ファイル名・寸法・保存日時も保存します。アップロードするだけで画像生成は始まりません。元画像と参照IDは、下書き・生成履歴・再生成にも保持します。

系統図ではアップロード画像に「アップロード」「参照の起点」を表示し、そこから生成した画像へ実線を引きます。複数の参照元もすべて表示します。起点を選ぶとファイル情報・プレビュー・タイトルとメモ・派生画像を確認できます。「この画像から生成」で、入力中の文章・テンプレート・設定を保ったまま参照を設定できます。同じ起点から別のプロンプトで作ると、別の枝として管理できます。

下書きの入力文・要素・参照・枚数・設定・制作の起点は、このブラウザのローカルストレージに保存します。エラー時や再読み込み後にも下書きを保持します。履歴から元の入力を読み込んで、当時の組み合わせを使えます。

入力の読み込みや例の選択で下書きを置き換えた場合は、制作画面の「元に戻す」で置き換え前の下書き全体に戻せます。この復元用の下書きも保存します。ブラウザデータを消すと下書きは消えますが、アプリ側の生成履歴とテンプレートは残ります。

## 同時作成のグループ表示

一度の操作でまとめて生成した画像は、履歴で「同時作成」の枠にまとめ、グループ番号と件数を表示します。カードは受付時の番号順に並べます。「系統図で見る」から、そのグループと参照元へ移動できます。系統図でも同じグループを淡い囲みと番号で示し、詳細のサムネイルから同じグループの画像を選べます。

保存済みの生成グループIDで判別するため、完成する順が前後しても同じグループを維持します。作成時刻が近いだけの別の生成はまとめません。検索・絞り込みや論理削除で一部だけ表示されるときは、表示件数と全件数・削除件数を区別します。グループ表示は参照や親子関係の記録を変更しません。

## 画像と下流ノードを削除する

生成履歴・キャンバス・拡大プレビューの「削除」、または系統図の詳細の「この画像と下流を削除」から対象を確認できます。アップロードした参照画像も、一覧や系統図から削除できます。確認画面には、選んだ画像と全下流ノードの一覧を表示します。生成画像・アップロード画像の件数と、停止する生成件数も表示します。

下流には、実際に画像を参照した派生だけでなく、入力を引き継いだ別案や再生成も含みます。複数の親を持つ画像も、削除したノードから到達できれば対象です。上流・別の枝・無関係な画像は保持します。確認後に下流が増えた場合は削除せず、更新した対象をもう一度表示します。

削除は論理削除です。履歴・系統図・参照候補から非表示にし、対象の生成中・待機中の処理を停止します。画像ファイルや生成時の文章・設定はディスクに残るため、削除でディスク容量は減りません。削除済み画像の参照・再生成・直接ダウンロードは拒否します。

履歴の「ゴミ箱」で削除グループをまとめて復元できます。別の削除グループや削除中の上流に含まれる画像は、そのグループを復元しても非表示を保ちます。中断された生成は復元しても自動で再開しません。削除履歴は`data/lineage.json`に保存し、再起動後にも保持します。

履歴上部の「エラー画像を一括削除」では、検索・絞り込み条件に関係なく、エラー状態の履歴だけを対象にします。件数と一覧を確認して「N件をゴミ箱に移動」を押すと削除します。完成済み・生成中・待機中・キャンセル済みの画像や、エラー画像から再生成した正常な画像は残ります。ゴミ箱から一括で復元できます。エラー画像を自動で削除することはありません。

## 失敗した場合の処理

| 状況 | 動作 |
| --- | --- |
| 通信・サービスの一時障害 | 結果が未確定になる前、またはツールが明確に一時障害を返した場合だけ、同じ入力で最大1回再試行 |
| 画像の内容判定・安全システムによる拒否 | 同じ文章・要素・参照・設定で、1.5秒待って最大2回自動再試行（初回を含め最大3回）。途中の拒否や再試行はUIに表示せず、履歴・系統図に画像や枝を追加しない。3回とも失敗した場合は「3回のリトライ上限に到達しました。」を表示。「内容を編集して再試行」で入力欄に復元 |
| 利用上限・認証エラー | 自動再試行せず、利用枠やログインの確認を案内 |
| 生成開始後の切断・タイムアウト | 処理状態が不明な場合は重複生成を避けて停止。入力を保持し、必要に応じて手動で再試行 |
| 完成画像を受信した後、最終応答だけ失敗 | 受信済みの画像を検証・保存して回収 |

内容判定が誤検知かどうかをアプリが判断することはできません。サービスの判定を回避する処理や、別認証・API課金への切り替えは行いません。未分類のエラーには汎用の案内を表示し、元の入力を保持します。

失敗した履歴の「エラーの詳細」では、Codexが返した理由を確認できます。画像ツールの空の失敗応答で最終説明が隠れないようにしています。公式のTurnErrorに含まれる利用上限・通信障害の種類と補足も保存します。詳細は認証情報をマスクし、1,200文字までに制限します。

内容判定による拒否は、最終説明から判別できた場合も自動再試行します。最終説明だけで一時障害を推測した場合や、生成開始後に結果が不明な場合は自動再生成しません。更新前に詳しい理由を保存していない履歴の原因は復元できません。

## 設定

必要な場合だけ`.env.example`を`.env`にコピーして設定してください。

| 設定 | 既定値 | 用途 |
| --- | --- | --- |
| `PORT` | `4317` | ローカルHTTPポート |
| `LAN_HOST` | 無効 | 同じWi-Fiのスマホ接続に使う、このMacのプライベートIPv4 |
| `CODEX_BIN` | `codex` | 公式CLIの実行ファイルパス |
| `CODEX_MODEL` | CLIが返すモデル一覧の既定モデル | アカウントで利用できるCodexモデル |
| `GENERATION_TIMEOUT_MS` | `600000` | 生成待ちの上限。30秒〜30分 |
| `GENERATION_CONCURRENCY` | `5` | 最大同時生成数。1〜10件 |
| `DATA_DIR` | アプリ内の`data` | 履歴・画像の保存先 |

ポートが使用中の場合は`PORT=4318 npm run dev`で起動できます。同じデータフォルダのサーバーを同時に複数起動することはできません。

## 同じWi-Fiのスマホで開く

`.env`の`LAN_HOST`に、このMacのWi-FiのプライベートIPv4を指定して起動します。例えば`LAN_HOST=192.168.11.11`です。待受はlocalhostと指定IPだけに限定し、未承認端末にはコード入力画面だけを表示します。画像・履歴・画面アセット・操作APIは端末の承認まで利用できません。

Macの制作画面で「スマホで開く」を選び、「承認コードを発行」を押します。同じWi-Fiのスマホで表示されたURLを開き、8桁のコードを入力してください。コードは5分間有効で、1台の承認にだけ使えます。端末の承認は8時間、またはアプリ停止まで有効です。Macの同じ画面から、すべての端末の承認を解除できます。

コードと端末の認証情報はメモリに保持し、ファイルには保存しません。下書きは各ブラウザに保存するため、Macとスマホで独立しています。通信は同じWi-Fi内のHTTPです。信頼できるネットワークで使い、インターネットには公開しないでください。MacのIPが変わった場合は`LAN_HOST`を更新して起動し直します。

## バックエンドの構成

ブラウザ → ローカルHTTPサーバー → `codex app-server`（stdio JSON-RPC） → ネイティブ画像生成ツール → PNG/JPEG/WebPをローカル保存、という流れです。

`codex exec --json`は、検証した0.156.1では画像の保存先をJSONイベントに含めませんでした。このため、公式CLIのapp-serverプロトコルで`item/completed`の`imageGeneration`と`savedPath` / `result`を受け取ります。外部の非公式ラッパーやChatGPT内部HTTPエンドポイントには依存しません。

`src/codex-adapter.ts`にCLIとの連携を集約し、Webサーバーとジョブ管理から分離しています。CLIの仕様変更があった場合は、このアダプターを更新できます。

Codex 0.156.1で提供されるツール名は`image_gen.imagegen`です。画像生成機能が使うCLI内の実行ホストは有効にしたまま、シェルや外部連携を無効にしています。

モデルは`model/list`の既定モデルを採用するため、既存のCLI設定に利用できないモデル名が残っていても引き継ぎません。`CODEX_MODEL`を指定する場合も、一覧に存在することを確認してから使用します。

## 認証と利用枠

生成前にCLIの`account/read`で`chatgpt`認証を確認します。APIキー認証の場合は生成を拒否します。子プロセスの`OPENAI_API_KEY` / `CODEX_API_KEY` / `CODEX_ACCESS_TOKEN` / `OPENAI_BASE_URL`も除外し、API課金への自動切り替えは行いません。

ChatGPT/Codexの契約プランに応じた利用上限・機能制限は適用されます。無制限や無料を保証するアプリではありません。画像生成ツールを利用できるかどうかは、CLIバージョン、モデル、アカウントの利用権限に依存します。接続表示で確認するのはログイン状態とCLI機能です。サーバー側の画像生成権限や残り利用枠までは保証しません。

## ローカル運用

- 既定のHTTP待受は`127.0.0.1`だけです。`LAN_HOST`を明示した場合は、Macに割り当てられたプライベートIPv4にも待受を追加します。Host / Originと端末認証、操作用トークンで接続を保護します。
- CLIは`shell: false`で起動し、画像の説明はJSON-RPCのテキストとして渡します。モデルのシェル、外部MCP、アプリ、ブラウザ、プラグイン、フック、エージェント委譲を無効にします。
- CLIの対話承認を自動で許可しません。対話が必要な場合はエラーとして表示します。
- 画像と履歴は`data/jobs/<ID>/`に保存し、Git管理対象から除外します。再起動時に未完了の生成は失敗として復旧し、勝手に再生成しません。
- サイズ・スタイル・透過は画像生成ツールへのリクエストです。最終的な寸法や背景はモデルが決定するため、指定どおりになることを保証しません。
- キャンセル時はCLIプロセスを停止します。停止前に処理された分の利用枠が返還されることは保証しません。
- 個人のPCでの利用を想定しています。インターネットや他の利用者への公開は対象外です。

## 検証

```sh
npm run check
npm test
npm run doctor
```

テストはローカルの偽CLIと一時データを使い、認証情報・契約枠を消費しません。実画像生成はWeb画面の「画像を生成する」から行います。

`npm run check`は画面・サーバー・共通処理・テスト・補助スクリプトを`strict`設定で型検査し、サーバーと画面をビルドします。`npm test`はビルド後に`dist/test/`のバックエンドテストとVitestの画面テストを実行します。画面テストだけを実行する場合は`npm run test:frontend`を使います。`npm run doctor`も実行前にサーバー側のTypeScriptをビルドします。

画面は`frontend/src/`、サーバーは`server.ts`と`src/`、両者で使うデータ型と処理は`shared/`、補助スクリプトは`scripts/`、バックエンドテストは`test/`にあります。画面の型検査には`tsconfig.json`、サーバー側の型検査と出力には`tsconfig.server.json`を使用します。Node.js用のソースでは、ビルド後に解決できるように相対importに`.js`を指定しています。TypeScriptは対応する`.ts`を型検査します。生成されるJavaScriptとソースマップはGit管理対象から除外しています。

## 派生とブランチ

「画像の派生とブランチ」では、画像を選んで元画像・プロンプト・テンプレート・生成条件を確認し、そこから続きを作れます。実際に参照した画像からの線は実線、元の入力を編集した別案や再生成のつながりは破線です。複数の参照画像を使った場合は、すべての参照元に線を表示します。

「この画像から派生」では、選んだ画像を参照にし、元の文章・テンプレートを入力欄に戻します。文章を編集して生成すると、元画像がブランチの最新であれば同じ枝の続きになります。過去の画像から生成した場合は自動で別の枝になります。「新しいブランチとして生成」にチェックすると、最新の画像からも明示的に分岐できます。

「同じ入力で再生成」では、生成時の文章・テンプレート・参照・設定をそのまま使って新しい枝に生成します。再生成元の完成画像を参照画像へ勝手に追加しません。当時のテンプレートを後から編集・アーカイブしていても、保存済みの入力を使用します。

「入力を編集して別案」では、当時の参照設定を保ったまま文章やテンプレートを編集し、新しい枝に別案を保存します。

各画像にはタイトルとメモ、各ブランチには名前を付けられます。これらを編集しても、生成時のプロンプトや参照画像の記録は変わりません。ブランチ・作品ごとの絞り込みと検索、拡大縮小で長い履歴をたどれます。絞り込んだ場合にも参照元を残し、どこから派生したかを確認できます。生成失敗やキャンセルも履歴に残ります。

系譜データは`data/lineage.json`に独立して保存します。画像ID、全参照元、入力元、操作種別、ブランチ、タイトル・メモ、生成時刻、入力のハッシュを保持します。画像と元の入力は引き続き`data/jobs/<ID>/`に保存します。既存の履歴も初回起動時に参照関係から移行し、画像は削除しません。旧履歴には残っていない再生成元や入力編集元を、推測で追加することはありません。
